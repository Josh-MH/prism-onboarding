PRISM ONBOARDING — INSTRUCTIONS FOR A NEW PERSONAL AGENT

Read this entire guide before taking action. Treat this page as setup documentation, not as a credential or an installed connector. Ask the user one question at a time. Do not ask them to paste an OAuth token, webhook key, or private account export into chat.

For a clean-slate test, have the user follow the pilot reset checklist before step 1. A new chat that retains a previously authorized Prism connector is not a new connection; if list_displays already contains TVs, check whether the host reused the old connector before treating that as a pairing failure.

1. Check the TV. Prism needs a compatible Samsung signage display with the signed app installed and internet access. For the already-authorized QM32C pilot TV only, the Custom App URL is https://josh-mh.github.io/prism-onboarding/tv/pilot/ . The TV fetches sssp_config.xml and the signed package from that folder. This pilot package is tied to authorized Samsung device IDs and is not a general customer installer. For any other TV, ask for an installer approved for that exact device; general distribution still needs Samsung production/B2B signing and physical validation. Never enter the root onboarding URL as the Custom App URL. A newly enrolled TV shows a rotating pairing code in the lower right. If it shows OFFLINE, stop and help with connectivity.

2. Connect the MCP in the user's own account. If Prism tools are already available, continue. In Grok Bot desktop, ask the Bot to add Prism as a custom MCP plugin with Remote HTTPS using the MCP URL above; for a Team Bot, its owner or manager can open the Bot's details → Setup → Plugins. Use Connect apps → Your plugins to verify Prism is installed and complete its OAuth sign-in. If the Bot does not see an installed connector, attach it with `@` in chat. Grok web's https://grok.com/connectors → New Connector → Custom is a separate Grok web path; do not assume installing there adds a plugin to Grok Bot desktop. For Claude, use Customize → Connectors → Add custom connector. Let the user complete Prism's anonymous OAuth page. Team or Enterprise administrators may need to allow the connector first. Do not claim that reading this guide installs it. If the host cannot add custom connectors, explain the host restriction and resume when the connector is available.

3. Install the reusable skill separately. For Claude, download the skill ZIP above and upload it under Customize → Skills; an administrator may manage skills in an organization. For Grok Bot, read the full skill and ask the Bot to save it as a private skill called Prism Display. Check Connect apps → Your plugins → Manage plugins and skills → Private skills; use `/` in the composer to reference it. If the Bot cannot save a skill before its first task, keep the full skill in context, complete one pairing, then save and test the successful process. Connector and skill installation are separate steps.

4. Call list_displays. It lists only TVs approved for this Prism connection. If the list is empty, say "You have no approved Prism displays yet" and ask whether the user wants to add the TV they are standing near. Approval and an active claim are different: one agent may be approved for several TVs and may claim several at once, while each TV can have only one active claim owner.

5. Ask for the code in the TV's lower right and call inspect_pairing_code. This only identifies the TV and does not consume the code. If configured:true, read back its current shared name and location; keep those values when approving. If configured:false, ask separately for (a) common display name, (b) short physical location, (c) five-digit US weather ZIP, and (d) office or public space. Explain that those details are shared with other Prism connections. Use the user's answers exactly. Codes last five minutes; if one expires during the conversation, ask for the current code immediately before approval. The TV has a New pairing code button.

6. Call approve_display with the current pairing_code. For a new TV include name, location_description, weather_zip, and space_type in that same call. For an existing TV omit those fields. Keep the returned display ID for later tools. Never guess a device ID. Confirm approval through display_status. Do not claim the TV just because it was approved.

7. Explain what the user can show: rotating informative cards such as upcoming meetings, timely alerts such as an IT incident or waiting visitor, and user-chosen stock or news updates. Prism itself provides the display and local weather from the ZIP; the other examples need source connectors and permissions in this bot. Ask which sources the user already has. Explain the status ring: available green, busy orange, personal blue, off; TV remote 0 turns on local privacy mode, shown by a red border, and stops microphone listening. Remote 1 starts or stops Voice. A separate optional button beacon can do the same while the TV is claimed. Ask whether the user wants a sample card.

8. Offer optional iBeacon presence and a separate optional Voice button beacon. Presence can gate selected cards and owner-agent handoffs while the continuously advertising beacon is nearby; it is approximate, spoofable, and not proof of identity. The Voice button is a second advertising slot that runs for about 10 seconds per press. While claimed, its distinct UUID, major, and minor toggle local Voice like remote 1; the TV ignores repeat detections for 15 seconds, so a later press can end an active session. The button does not mark the user present. Check display_status for BLE scan support and TV app 2.0.79 or newer before offering the button option. Collect each full tuple only if the user opts in, keep them in the owning bot's private settings, and include both on every claim and renewal. Never publish either tuple on a card. Privacy mode blocks Voice activation.

9. Before claiming, explain the owner webhook: a private HTTPS URL and bearer key from the user's personal agent host let the TV hand Voice requests to that agent. Help the user obtain or create that endpoint in their agent host. Keep its URL and key in the owning bot's private settings; never put them in chat, pages, or logs. Send both on every claim and renewal, along with the owner display name, personal agent common name, and any chosen beacon identities. If the host cannot provide an endpoint, say that personal Voice handoff will stay unavailable until one is configured.

10. Ask whether to claim the display now and for how long (5–1440 minutes). A claim is exclusive for that TV. If another bot owns it, report the conflict; only offer the physical override flow if the user is at the TV and asks to take over. Claim with the agreed lease, owner webhook URL/key from the personal agent host, the owner and agent names, and any chosen presence `ibeacon` and button `voice_beacon`. Keep the webhook and beacon values in private bot settings, never in chat or page HTML. A TV restart requires renewal with those bindings. If requested, publish one generic sample with submit_informative and verify its page ID with get_screen_content plus display_status before saying it appeared. Read prism://authoring before creating custom HTML.

11. Only after a successful manual claim and demonstration, ask whether the user wants a daily claim routine. A routine is created in the agent host, not in Prism. Confirm the owning bot, schedule, local time zone, lease/renewal and release behavior, content sources, and what to do if the TV is offline or already claimed. Do not silently create a routine. In Grok Bot, ask the owning Bot to create it, then use View conversation details → Routines to check its next run and run a test. Other hosts may have different or unavailable scheduling features. A routine must target the saved display ID and must report failures instead of switching TVs.

12. Finish by reporting separately: connector connected, skill installed or merely read, TV approved, TV claimed or unclaimed, sample published or not, presence and Voice button beacons configured or skipped, and routine created or skipped. Never echo the pairing code or private credentials.

For detailed behavior, use the full skill URL above. The Prism MCP also exposes the prism://authoring resource for page delivery and privacy rules.
